# Perf v3 — baseline (этап 0)

Точка отсчёта: коммит `91d5e67` (архитектура neuron-v2 как есть), ветка `feat/perf-v3`.
Все числа ниже сняты **до первой правки**. Правки в этом коммите — только
измерительная обвязка: `docs/perf-v3/harness.js` (подключается сборкой с
`NEXT_PUBLIC_PERF_HARNESS=1`, в прод не попадает), `performance.mark` в сцене,
принудительный тир через `/?tier=low|mid|high`.

## Окружение

| | |
|---|---|
| Машина | MacBook Air 13" (Apple M3, 8 ядер, 16 ГБ) |
| Браузер | Chrome 152, отдельный профиль, `--disable-gpu-shader-disk-cache` (компиляция шейдеров всегда «холодная», как у первого посетителя) |
| Окно | встроенный дисплей **60 Гц**, эмуляция вьюпорта 1440×900 @ DPR 2 |
| Сервер | `next build` + `next start` на :3000; вместо Spring-бэкенда фикстурный сервер на :8080 (`tools/mock-backend.mjs`): 12 услуг, 6 врачей, картинки из `public/` |
| Драйвер | `tools/cdp.mjs` — Chrome DevTools Protocol из Node без зависимостей: трассировка (`devtools.timeline`), LayerTree, Network, скриншоты |
| Реальный мобильный | **нет** — не подключён. Тир `low` здесь — это «ноутбук с форсированным профилем low», не телефон |

### Две ловушки, найденные по ходу

1. **Внешний 5K-монитор владельца работает на 30 Гц** (`system_profiler`: «UI Looks like 2560×1440 @ 30.00Hz», он же Main Display).
   На нём `requestAnimationFrame` идёт с шагом 33,3 мс у любой страницы, включая `about:blank`, — первая серия замеров
   показала медиану 33,3 мс во всех вариантах, даже без canvas. Всё, что ниже, снято на встроенном дисплее (60 Гц).
   Для владельца это означает: на этом мониторе любая анимация — прелоадер, нейрон, скролл — физически идёт 30 к/с, и
   никакая правка кода этого не изменит. Плюс следствие для сцены: `PerformanceGuard` меряет интервал кадра, на 30 Гц
   он всегда 33 мс > бюджета 22 мс → тир понижается с `high` до `mid` через ~4,5 с после монтирования. На 30-герцовом
   мониторе гвард принимает медленный дисплей за медленное железо (см. `outlier-first-launch-load-high.json`, метки
   `neuron:build:*:mid` на 6,4 с).
2. **Самый первый запуск свежего профиля Chrome** дал 4,2 с long tasks внутри занавеса (1,29 с — блокировка на
   создании WebGL-контекста в коммите React, 2,28 с — первый рендер сцены) и занавес длиной 7,5 с. Повторить это не
   удалось ни холодным HTTP-кэшем, ни отключённым кэшем шейдеров: в дальнейших холодных запусках те же две задачи —
   52 мс и 155 мс. Считаю это стоимостью первого запуска GPU-процесса Chrome (кэш Metal-шейдеров ANGLE на уровне ОС),
   а не свойством страницы; файл сохранён как outlier.

## Загрузка

Запись от навигации до снятия занавеса. «Холодный» — `Network.clearBrowserCache` перед навигацией (JS
скачивается заново, V8 code cache пуст); кэш шейдеров отключён всегда.

| замер | TTFB | FCP=LCP | CLS | TBT | занавес (мс) | long tasks в занавесе | JS при загрузке |
|---|---|---|---|---|---|---|---|
| high, холодный | 21 | 160 | 0 | 144 | 3758 | 2 / 206 мс | 517 KB (18 файлов) |
| high, тёплый | 14 | 96 | 0 | 36 | 3736 | 1 / 86 мс | 0 (кэш) |
| mid, холодный | 27 | 244 | 0 | 23 | 3820 | 1 / 73 мс | 517 KB |
| low, холодный | 19 | 112 | 0 | 0 | 3757 | 0 | 517 KB |

Раскладка long tasks (high, холодный): `52 мс` — сборка геометрии (25 мс, метки `neuron:build`) + создание
рендерера; `155 мс` — первый кадр сразу после `neuron:gl-created`: компиляция шейдеров MeshPhysicalMaterial с
transmission, запекание `Environment`, программы SSAO/DoF/Bloom. На `mid` тот же первый кадр — 73 мс, на `low`
задача не дотягивает до 50 мс.

Занавес: **3,74–3,82 с**, ровно по арифметике таймлайна (3,68 с) плюс монтирование. Первый кадр анимации букв —
90–290 мс от навигации. GSAP приходит в критическом бандле: чанки `3o-hjqbfzjqd4` (27 KB) и `29_8qleul54dg` (18 KB)
грузятся до первого кадра.

**TTFB 14–27 мс** — с фикстурным бэкенде на localhost; `force-dynamic` + два запроса к CMS на каждый просмотр
подтверждены логом фикстуры (проверка D1 — в отчёте).

### Вердикт B1 — что дало наибольший выигрыш

На этой машине скролл **уже идёт 58–60 к/с при 60 Гц**: главный поток занят 8–15 %, GPU — 9–14 % времени.
Ни одна из гипотез не «спасает fps», потому что спасать нечего; смотреть надо на стоимость, а не на кадры:

- **`theme.apply` (запись `--page-bg`/`--scene-dark` на `:root`)** — главный виновник обеих статей: Recalculate Style
  падает вдвое (265–302 → 142 мс на high, 369 → 120 на mid), GPU — на 25–45 % (1077 → 725 на high, 1388 → 749 на mid).
  Запись переменной на корень инвалидирует стили всего документа, и композитор пересобирает размытие под всеми
  стеклянными слоями. → **основная работа — B3.**
- **`--glass-blur: none`** — style-время не уменьшает (размытие считает GPU, а не главный поток), GPU −8…−27 %,
  −19 слоёв. → B2 — вторая по значимости, и это единственное, что поможет слабому GPU (мобильный).
- Вклад собственно three.js: удаление canvas снижает GPU лишь до 779 мс — то есть **рендер нейрона стоит меньше,
  чем стекло + перекраска страницы**, диагноз промпта в этой части подтверждён.

Что из этого следует для жалобы «нейрон дёргается»: на M3 + 60 Гц дёргаться нечему — сцена под потолком
`fps: 60` идёт вровень со страницей. На **30-герцовом внешнем мониторе** владельца сцена и страница идут 30 к/с, гвард
дополнительно понижает тир до `mid`, а там потолок `fps: 40` через `FrameDriver` даёт кадры через раз (C6). Ступенчатость
(C7) реальна на 60-герцовом экране с тиром `mid`/`low`: сцена 30 к/с под текстом 60 к/с.

## Что не замерено и почему

- **Реальный мобильный девайс** — не подключён; критерий «≥ 30 к/с на телефоне» остаётся за владельцем.
- **Раскладка по слоям в Layers panel «сколько стоят `::after`»** — CDP отдаёт число слоёв и размеры, но не
  стоимость каждого; по разнице 50 → 31 стекло даёт 19 слоёв, псевдоэлементы-блики отдельными слоями не видны.
- **Прокрутка колесом** заменена программной прокруткой в rAF: она идёт через главный поток, а не через композитор,
  то есть чуть пессимистичнее реальной.

## Как воспроизвести

```
# фикстурный бэкенд (терминал 1)
node docs/perf-v3/tools/mock-backend.mjs
# сборка с обвязкой и сервер (терминал 2)
NEXT_PUBLIC_PERF_HARNESS=1 npm run build && npm run start
# Chrome с CDP, окно — на 60-герцовом дисплее (терминал 3)
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --remote-debugging-port=9222 \
  --user-data-dir=/tmp/perf-profile --disable-gpu-shader-disk-cache --window-size=1280,760 about:blank
# замеры (терминал 4); результаты — JSON в $S/results
S=/tmp/perf COLD=1 node docs/perf-v3/tools/cdp.mjs load high-cold "http://localhost:3000/?tier=high"
S=/tmp/perf node docs/perf-v3/tools/cdp.mjs scroll high "http://localhost:3000/?tier=high" none 10
S=/tmp/perf node docs/perf-v3/tools/cdp.mjs scroll high-glass-none "http://localhost:3000/?tier=high" glass-none 10
S=/tmp/perf node docs/perf-v3/tools/cdp.mjs reload reload "http://localhost:3000/"
S=/tmp/perf node docs/perf-v3/tools/summarize.mjs /tmp/perf/results
```

Сырые результаты этого этапа — `data/baseline/*.json`.
