# Витрина блога: показ AI-статей из CMS — Design

**Дата:** 2026-08-25
**Статус:** утверждён к реализации

## Цель

Показать на витрине статьи, которые бекенд уже генерирует и публикует, в типографике сайта — с выраженной иерархией шрифтов и кеглей и с картинками.

Три измеримых результата:

1. `/blog` отдаёт список опубликованных статей, `/blog/<slug>` — статью; обе страницы попадают в `sitemap.xml`, вход в раздел есть в основной навигации.
2. Модельный HTML не доходит до браузера как `innerHTML`: страница собрана из React-элементов, построенных по белому списку тегов и атрибутов.
3. Статья несёт разметку `Article` и — когда в тексте есть блок «Частые вопросы» — `FAQPage`.

## Охват

**В охвате:** страницы `/blog` и `/blog/[slug]`, парсер статейного HTML, детерминированный подбор картинок из существующих ассетов, пункт в `NAV_LINKS`, записи в `sitemap.ts`, тесты парсера и подбора картинок.

**Вне охвата:** правки бекенда (Java, схема БД, промпт), раздел блога в админке, блок «Последние статьи» на главной, подсветка активного пункта оглавления при скролле, поиск и теги по статьям. Всё это — отдельные работы.

## Решения, принятые до начала работы

Приняты пользователем в ходе брейншторма. Менять их в реализации нельзя.

1. **Картинки — курируемый набор на фронте.** Подбираются из уже лежащих в `/public` фото по тексту поста. Поля обложки в бекенде не появляется, правок Java нет.
2. **HTML разбирается на сервере в структуру блоков** и рендерится React-компонентами. Не `dangerouslySetInnerHTML`, не резка регэкспом по `<h2>`.
3. **Парсер — `node-html-parser`.** Одна новая зависимость, только серверный рантайм.
4. **Характер страницы статьи — редакторская одноколонка:** мера ~68ch, обложка 21:9 с заголовком поверх, лид крупнее корпуса, ЭЭГ-линия как разделитель перед `h2`, FAQ на стекле, sticky-оглавление справа на широком экране.
5. **Объём — `/blog` + `/blog/[slug]` + пункт в меню.** Без блока на главной: он затрагивает `HomeShell`/`NarrativeActs` и отлаженный скролл-сценарий сцены нейрона.
6. **Тесты — vitest.** Первый тест-раннер в проекте.

## Что есть на бекенде

Отправная точка — `CMS-premium`, класс `ContentGenerationService`.

**Генерация.** YandexGPT по системному промпту возвращает JSON `{title, body, metaDescription, keywords}`. `body` — HTML, прогнанный через `Jsoup.clean(Safelist.relaxed().removeTags("img"))`. Промпт задаёт структуру: первый абзац — прямой сжатый ответ на вопрос темы, `<h2>` сформулированы как вопросы, абзацы по 2–4 предложения, перечисления через `<ul>`/`<ol>`, в конце `<h2>Частые вопросы</h2>` и 3–5 пар `<h3>`/`<p>`, последняя строка — про необходимость очной консультации.

**Публикация.** Пост создаётся как `DRAFT`, ревью идёт через Telegram (`TelegramUpdateListener` → `PostReviewService.approve`) и переводит `status` в `PUBLISHED`. `PageStatus` — это ровно `DRAFT | PUBLISHED`.

**API.** `GET /api/cms/blog` — только опубликованные. `GET /api/cms/blog/{slug}` — анонимам только опубликованный, стаффу любой. `GET /api/cms/blog/all` — стаффу.

**Два ограничения, которые формируют дизайн:**

| # | Ограничение | Следствие |
|---|---|---|
| 1 | `img` вырезан из `Safelist` намеренно, поля обложки у `BlogPostEntity` нет | картинки не могут прийти из данных — их подбирает фронт |
| 2 | `sourceTopic` есть в сущности, но **не отдаётся** в `BlogPostResponseDto` | подбор идёт по `title` + `keywords` + `slug`, а не по идентификатору темы |

## Чего нет на фронте

Блога нет вообще: ни страниц, ни типа `BlogPost`, ни функций в `lib/cms.ts`, ни пункта в `NAV_LINKS`, ни записей в `sitemap.ts`. Тест-раннера в проекте тоже нет.

## Архитектура

Четыре слоя, каждый не знает о соседях:

| Файл | Ответственность | Зависит от |
|---|---|---|
| `lib/types.ts` | тип `BlogPost` | — |
| `lib/cms.ts` | `listBlogPosts()`, `getBlogPostBySlug()` | `fetchCms` (есть, ISR 3600 c) |
| `lib/blog/article.ts` | чистый парсер: HTML → структура блоков | `node-html-parser` |
| `lib/blog/images.ts` | чистый подбор ассетов: пост → обложка + врезки | — |
| `app/(site)/blog/**`, `app/(site)/components/blog/**` | вёрстка | всё выше |

**Поток данных.** RSC-страница → `fetchCms` → `BlogPost` → `parseArticle(post.body)` на сервере → массив блоков → React-компоненты.

`dangerouslySetInnerHTML` не используется нигде. Инлайновая разметка внутри абзацев (`strong`, `em`, `code`, `a`, `br`) тоже превращается в структуру, и `ArticleBody` рендерит её рекурсивно. В браузер уходит только то, чьи теги и атрибуты перечислены в парсере: Jsoup на бекенде — первый слой защиты, белый список парсера — второй, независимый от того, ослабят ли когда-нибудь `Safelist`.

## Контракт данных

Зеркало `BlogPostResponseDto`:

```ts
export interface BlogPost {
    id: number;
    slug: string;
    title: string;
    body: string;                     // санитизированный HTML из CMS
    metaDescription: string | null;
    keywords: string | null;
    status: "DRAFT" | "PUBLISHED";
    aiGenerated: boolean;
    createdAt: string;
    updatedAt: string;
}
```

`listBlogPosts()` идёт в `/api/cms/blog`, при недоступном бекенде возвращает `[]` (поведение `fetchCms`). `getBlogPostBySlug(slug)` идёт в `/api/cms/blog/{slug}` и возвращает `null` на любой не-200.

`createdAt` — это Java `LocalDateTime`. Ожидаемая сериализация — ISO-строка `2026-08-25T12:34:56`; это проверяется на живом ответе в первой же задаче реализации. Форматтер даты обязан терпеть и строку, и массив чисел, и мусор — при нераспознанном значении дата просто не выводится, страница не падает.

## Контракт парсера

`lib/blog/article.ts` — чистая функция, ничего не знает о React:

```ts
export type Inline =
    | { kind: "text"; text: string }
    | { kind: "strong" | "em" | "code"; children: Inline[] }
    | { kind: "br" }
    | { kind: "link"; href: string; external: boolean; children: Inline[] };

export type Block =
    | { kind: "p"; content: Inline[] }
    | { kind: "h3"; content: Inline[] }
    | { kind: "quote"; content: Inline[] }
    | { kind: "list"; ordered: boolean; items: Inline[][] };

export interface Section { id: string; heading: string; blocks: Block[] }
export interface FaqItem { question: string; answer: Block[] }

export interface Article {
    lead: Inline[] | null;   // первый <p> до первого <h2> — идёт крупным кеглем
    intro: Block[];          // остальные блоки до первого <h2>
    sections: Section[];     // без FAQ-секции
    faq: FaqItem[];
    plainText: string;       // для времени чтения и фолбэка мета-описания
    readingMinutes: number;
}

export function parseArticle(bodyHtml: string): Article;
```

### Правила нормализации

Это и есть второй слой защиты, поэтому список закрытый.

- **Белый список блоков:** `h2`, `h3`, `p`, `ul`, `ol`, `blockquote`.
- **`h1` понижается до `h2`**, `h4`–`h6` поднимаются до `h3`. На странице `h1` уже занят заголовком поста; вторая первая сущность сломала бы иерархию для скринридеров и разметки.
- **`div` и `span` на верхнем уровне разворачиваются в детей** — `Safelist.relaxed` их пропускает.
- **Всё прочее** (`table`, `pre`, случайный мусор) → берётся только текстовое содержимое и оборачивается в абзац. Контент не теряется, вёрстка не ломается.
- **Белый список инлайна:** `strong`, `b`, `em`, `i`, `code`, `br`, `a`. `b` → `strong`, `i` → `em`. Остальные инлайновые теги разворачиваются в текст.
- **Ссылки:** остаются только `https:`, `http:`, `mailto:`, `tel:` и относительные, начинающиеся с `/`. `javascript:`, `data:` и всё непонятное → ссылка вырождается в обычный текст.
- **`external: true`** ставится только у `http(s)`-ссылок на чужой домен; такие получают `target="_blank" rel="nofollow noopener"` — модельные ссылки не должны передавать вес сайта. `mailto:`, `tel:` и относительные — `external: false`, без `target`.
- **Атрибуты не пробрасываются.** Ни один, кроме `href` у разрешённых ссылок.
- **Вложенные списки сплющиваются** в родительский. Промпт просит простые перечисления, но терять текст на неожидаемой вложенности нельзя.
- **FAQ:** секция с заголовком по `/частые\s+вопросы|вопросы\s+и\s+ответы|^faq$/i` вынимается из `sections`; внутри пары «`h3` + блоки до следующего `h3`» становятся `faq[]`. Нет такой секции — `faq` пустой, блок не рендерится, `FAQPage` не выводится.
- **`id` секций** — `s1…sN` по порядку. Стабильные и уникальные без транслитерации кириллицы.
- **Время чтения:** `Math.max(1, Math.round(words / 180))`.
- **Пустой или мусорный `body`:** `Article` с `lead` из первых предложений `plainText` и пустыми `sections`. Исключения не летят.

## Контракт подбора картинок

```ts
export function pickArt(post: BlogPost, sectionCount: number):
    { cover: string; coverAlt: string; inline: string[] };
```

Таблица правил по `` `${title} ${keywords} ${slug}` `` в нижнем регистре, первое совпадение выигрывает:

| Регэксп | Ассет |
|---|---|
| `эпилепс\|приступ\|ээг\|память\|концентрац\|сон\|бессонниц` | `services/eeg.png` |
| `поясниц\|спин\|грыж\|диск\|седалищн\|защемлен` | `services/blocade.png` |
| `онемен\|покалыван\|невропат\|тремор\|лицев` | `services/elektro.png` |
| `инсульт\|восстановлен\|реабилитац` | `services/capelnic.png` |
| `головокружен` | `services/uzi2.png` |
| `мигрен\|головн\|напряжен` | `services/massage.png` |
| `приём\|обследован\|анализ` | `services/anal.png` |
| фолбэк | фото из `clinic/` по хешу slug |

Фото услуг — настоящие снимки ~1280×853, для обложки 21:9 годятся.

`coverAlt` описывает **то, что на фото**, а не заголовок статьи: снимок процедурного кабинета не является изображением мигрени, и подпись «Мигрень и головная боль напряжения» для скринридера была бы ложью. Альт хранится в таблице рядом с ассетом.

Врезки в тексте берутся из пула `clinic/*.jpg`; портретный `clinic4.jpg` (853×1280) из пула исключён. Одна врезка при `sectionCount >= 3`, две при `>= 6`; вставляются после 2-й и после 5-й секции.

Выбор из пула — по FNV-хешу slug, **никакого `Math.random`**: при ISR страница рендерится многократно, и случайный выбор давал бы разную картинку в разных копиях кеша. Врезка не повторяет обложку.

## Вёрстка

### Типографическая шкала

| Роль | Токен шрифта | Размер / интерлиньяж |
|---|---|---|
| `h1` статьи | `--font-head` | `clamp(2.1rem, 4.6vw, 3.4rem)` / 1.08, трекинг −0.01em |
| Мета (дата · N мин) | `--font-body` | 0.875rem, `--ink-soft`, `text-transform: uppercase`, трекинг +0.04em |
| Лид-абзац | `--font-body` | `clamp(1.15rem, 1.9vw, 1.35rem)` / 1.6, цвет `--ink` |
| `h2` секции | `--font-head` | `clamp(1.6rem, 3vw, 2.15rem)` / 1.2 |
| Корпус | `--font-body` | `clamp(1.0625rem, 1.3vw, 1.125rem)` / 1.75, мера 68ch |
| `h3` в тексте | `--font-body` 600 | 1.15rem / 1.4 |
| Вопрос в FAQ | `--font-body` 600 | 1.05rem |

Лид намеренно набран цветом `--ink`, а не `--ink-soft`: по промпту это прямой ответ на вопрос темы, главное предложение статьи.

Раскладка строится на существующих токенах: `--container`, `--gutter`, `--section-y`, `--radius-lg`, `--glass-*`. Новых глобальных токенов не вводится.

### Компоненты

| Компонент | Что делает |
|---|---|
| `blog/page.tsx` | индекс: `h1` «Блог», сетка карточек 3→2→1, первая карточка на всю ширину как ведущая |
| `components/blog/BlogCard.tsx` | стеклянная карточка: обложка 3:2, дата, заголовок `--font-head`, мета-описание с обрезкой в 2 строки |
| `blog/[slug]/page.tsx` | обложка 21:9 с градиентным затемнением снизу, `h1` и мета поверх неё |
| `components/blog/ArticleBody.tsx` | лид → `intro` → секции с ЭЭГ-разделителем перед `h2` → врезки → FAQ |
| `components/blog/ArticleToc.tsx` | sticky-оглавление справа от 1100px; обычные якорные ссылки, ноль JS |
| `components/blog/ArticleFaq.tsx` | нативные `<details>`/`<summary>` на стекле |

На узких экранах заголовок статьи уезжает **под** обложку, а не лежит поверх: текст на фото при 360px нечитаем, сколько бы затемнения ни лить.

Оглавление — обычные якоря без клиентского JS. Подсветка активного пункта при скролле потребовала бы клиентского компонента и вне охвата.

FAQ на нативных `<details>` работает с клавиатуры и попадает в поиск по странице без единой строчки скриптов.

### SEO

- `generateMetadata`: `title`, `description` (`metaDescription`, а при пустом — первые 160 символов `plainText`), OpenGraph с обложкой и `publishedTime`, канонический URL.
- JSON-LD массивом в одном `<script type="application/ld+json">`: `Article` всегда, `FAQPage` при непустом `faq`. Системный промпт бекенда прямо заставляет модель писать блок FAQ ради попадания в ответы поисковых AI — без разметки половина этой работы теряется.
- `generateStaticParams` из `listBlogPosts()`. Бекенд недоступен на билде → пустой массив, страницы рендерятся по первому запросу.
- `/blog` и все статьи добавляются в `app/sitemap.ts` рядом с услугами.

## Отказы

| Ситуация | Поведение |
|---|---|
| `BACKEND_URL` не задан или бекенд недоступен | `/blog` показывает пустое состояние «Статей пока нет» |
| Пост не найден, 404 от бекенда | `notFound()` → штатная 404 |
| Пришёл пост со `status: "DRAFT"` | `notFound()` — страховка на нашей стороне, если права на бекенде ослабят |
| `createdAt` в неожидаемом формате | дата не выводится, страница рендерится |
| `body` пустой или неразбираемый | рендерятся заголовок, обложка и извлечённый текст |
| Ссылка со схемой `javascript:` в тексте | остаётся текстом, атрибут `href` не создаётся |

## Тесты

vitest, первый тест-раннер в проекте. Тестируются два чистых модуля; компоненты и страницы не тестируются.

`lib/blog/article.test.ts`:

1. Лид — это первый `<p>` до первого `<h2>`; последующие абзацы уходят в `intro`.
2. Каждый `<h2>` открывает секцию; блоки до следующего `<h2>` попадают в неё.
3. Секция «Частые вопросы» вынута из `sections` и разобрана в пары вопрос/ответ.
4. Нет секции FAQ → `faq` пустой, остальные секции целы.
5. `<h1>` в теле стал `h2`, `<h4>` стал `h3`.
6. Вложенный `<ul>` внутри `<li>` сплющен, ни один пункт не потерян.
7. `<a href="javascript:...">` вырождается в текст; внешняя ссылка помечена `external`.
8. `<script>`, `<img>`, `onclick` не дают ни узлов, ни атрибутов.
9. Пустая строка и HTML без блочных тегов не бросают исключение.
10. Время чтения — минимум 1 минута.

`lib/blog/images.test.ts`:

1. Каждое правило таблицы отдаёт свой ассет.
2. Пост без совпадений получает фолбэк из `clinic/`.
3. Два вызова с одним slug дают идентичный результат (детерминизм).
4. Врезка никогда не совпадает с обложкой.
5. Число врезок зависит от `sectionCount` по правилу 3/6.

## Критерии приёмки

1. `npx tsc --noEmit` и `npm test` проходят.
2. `npm run build` собирается; `/blog` и `/blog/<slug>` отдают серверный HTML с `h1` внутри.
3. В сохранённом HTML страницы статьи нет `<script>` из тела поста, нет `on*`-атрибутов и нет `href="javascript:` — проверяется грепом по ответу `curl`.
4. `/blog` при выключенном бекенде отдаёт пустое состояние, а не ошибку.
5. Статья с блоком «Частые вопросы» отдаёт валидный `FAQPage` в JSON-LD.
6. Пункт «Блог» виден в основной навигации и в мобильном меню; `/blog` и статьи есть в `sitemap.xml`.
