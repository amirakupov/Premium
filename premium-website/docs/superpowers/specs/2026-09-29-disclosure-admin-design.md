# Раскрытие информации и документы через админку — дизайн

**Дата:** 2026-09-29
**Статус:** принято владельцем, ждёт ревью спеки
**Связано:** `2026-09-17-659-compliance-design.md` (план A сделан; эта спека
меняет его допущение «бэкенд не меняется»)

## Задача

Убрать хардкод раздела «Раскрытие информации». Сейчас реквизиты, список PDF,
страховые компании по ДМС и контролирующие органы лежат в `lib/disclosure.ts`
и `public/docs/`: чтобы заменить прейскурант — который по Постановлению № 659
обязан совпадать с кассой, — нужен деплой. Администратор должен сам
добавлять, заменять, упорядочивать и удалять документы через админку, а
изменения — появляться на сайте без деплоя.

Документы бывают двух владельцев: клиника (раздел раскрытия) и конкретный
врач (сертификаты, дипломы — план B). Хранилище и загрузка общие.

**Критерий готовности:** администратор загрузил в админке скан лицензии — и
при следующем заходе он открывается на `/documents`; в `lib/disclosure.ts` и
`public/docs/` не осталось данных раскрытия.

## Решения владельца

1. Документы — и клиники, и врачей. Клиника в этом плане, врачи — в плане B
   на той же модели и тех же компонентах.
2. В админку переносится всё: документы, реквизиты, ДМС, контролирующие
   органы. В коде остаются только разметка и юридическая формулировка про ОМС.
3. Документ — либо загруженный PDF, либо внешняя ссылка (программа
   госгарантий публикуется на сайте Минздрава РБ).
4. Подход — отдельные сущности (а не JSON-настройки и не страница
   `PageEntity` в markdown): валидация на бэкенде, естественная привязка к
   врачу, схема как у существующих сущностей.

## 1. Модель данных

Таблицы создаёт Hibernate (`ddl-auto: update`), миграций в проекте нет.

### `DisclosureDocumentEntity` — `disclosure_documents`

| Поле | Тип | Примечание |
|---|---|---|
| `id` | Integer, IDENTITY | |
| `title` | String, not null, ≤ 300 | |
| `category` | enum `DocumentCategory`, not null | см. ниже |
| `kind` | enum `DocumentKind` (`FILE`, `LINK`), not null | |
| `url` | String, not null | `/uploads/<uuid>.pdf` для `FILE`, `https://…` для `LINK` |
| `note` | String, ≤ 500, nullable | |
| `sortOrder` | Integer, not null | порядок внутри категории |
| `doctor` | `@ManyToOne(LAZY)` → `DoctorsEntity`, nullable | `null` — документ клиники |
| `updatedAt` | LocalDateTime | `@PrePersist` / `@PreUpdate`, как в `PageEntity` |

`DocumentCategory`:
- клиника: `CONTRACT`, `PRICE_LIST`, `LICENSE`, `REGULATION`,
  `GUARANTEE_PROGRAM`, `OTHER`;
- врач: `CERTIFICATE`, `DIPLOMA`.

Категория определяет место на сайте: `GUARANTEE_PROGRAM` — в блоке ОМС,
остальные категории клиники — в списке «Документы» в порядке перечисления
выше. Категории врача на `/documents` не выводятся никогда.

Обязательные для раскрытия категории (для бейджа «Не хватает»):
`CONTRACT`, `PRICE_LIST`, `LICENSE`, `REGULATION`, `GUARANTEE_PROGRAM`.

### `ClinicRequisitesEntity` — `clinic_requisites`

Одна строка, `id = 1`. Поля: `legalName`, `shortName`, `inn`, `kpp`, `ogrn`,
`registeredAt` (LocalDate), `legalAddress`, `actualAddress`. Все nullable:
пустое поле сайт не печатает. Форматы строковых кодов — `@Pattern`, пустая строка
допустима: ИНН `^\d{10}$`, КПП `^\d{9}$`, ОГРН `^\d{13}$`.

### `DmsPartnerEntity` — `dms_partners`

`id`, `name` (not null), `site` (nullable, только `https://`), `sortOrder`.

### `RegulatorEntity` — `regulators`

`id`, `name` (not null), `address`, `phone`, `site` (только `https://`),
`sortOrder`.

### Сознательно не делаем

- Черновиков и статуса публикации: документ публикуется при сохранении.
  Новый прейскурант — замена файла в той же записи.
- Истории версий: постановление требует показывать действующий документ.
- Удаления файла с диска при удалении записи: имена — UUID, мусор безвреден,
  а ошибочное удаление записи восстанавливается повторной привязкой файла.

## 2. API и безопасность

Все пути под существующими правилами `SecurityConfig`, новых правил нет.

### Витрина

`GET /api/cms/disclosure` → `{ requisites, documents, dmsPartners, regulators }`.
`documents` — только `doctor = null`, отсортированы по категории, затем по
`sortOrder`. Анонимный доступ — через `GET /api/cms/** permitAll`.

### Админка

| Метод | Путь | Роль |
|---|---|---|
| GET | `/api/cms/documents?doctorId=` | открыт (черновиков нет) |
| POST | `/api/cms/document` | ADMIN |
| PATCH | `/api/cms/document/{id}` | ADMIN, EDITOR |
| DELETE | `/api/cms/document/{id}` | ADMIN |
| PATCH | `/api/cms/documents/order` — тело `{ ids: number[] }` | ADMIN, EDITOR |
| PATCH | `/api/cms/requisites` — upsert строки `id = 1` | ADMIN, EDITOR |
| POST / PATCH / DELETE | `/api/cms/dms-partner[/{id}]` | как у документов |
| PATCH | `/api/cms/dms-partners/order` | ADMIN, EDITOR |
| POST / PATCH / DELETE | `/api/cms/regulator[/{id}]` | как у документов |
| PATCH | `/api/cms/regulators/order` | ADMIN, EDITOR |

Реквизиты — `PATCH`, а не `PUT`: у `PUT` нет правила, и он упал бы в
`anyRequest().authenticated()`, то есть был бы доступен любому вошедшему.

`/order` принимает полный список id одной группы (категории документов, или
всех партнёров, или всех органов) и проставляет `sortOrder` по позиции. Id не
из группы или неполный список — 400.

### Загрузка PDF

`POST /api/cms/media/document`, multipart, поле `file`, ADMIN.

- Расширение `.pdf` и сигнатура `%PDF-` в первых пяти байтах; иначе 400.
- Размер ≤ 30 МБ. В `application.yml`: `max-file-size: 30MB`,
  `max-request-size: 32MB`. Лимит картинок (10 МБ) остаётся проверкой в
  коде `MediaController`.
- Файл пишется в `app.upload-dir` без обработки как `<uuid>.pdf`, ответ
  `{ url: "/uploads/<uuid>.pdf", size }`. Раздаётся существующим
  `/uploads/**`, `Content-Type: application/pdf`.

Путь со стороны Next: **route handler**
`app/api/admin/upload-document/route.ts`, а не server action. Лимит тела
server actions (`6mb` в `next.config.ts`) общий для всех actions, и тело
буферизуется в памяти — поднимать его до 30 МБ нельзя. Route handler
стримит тело на бэкенд (`duplex: "half"`), пробрасывая `cookie` и
`content-type`; права проверяет только бэкенд.

### Валидация ссылок

`kind = LINK`, `site` у партнёров и органов — только `https://` (защита от
`javascript:` и прочих схем в `href`). `kind = FILE` — только `url`,
начинающийся с `/uploads/` и оканчивающийся на `.pdf`.

### Ошибки

`@Valid` + `@Pattern` → 400 с текстом через `GlobalExceptionHandler`;
админка выводит его у поля.

## 3. Админка

Пункт «Раскрытие информации» в `Sidebar` (`/admin/disclosure`,
`FiFileText`, счётчик — число документов клиники). Четыре вкладки, активная —
в `?tab=` (`documents` по умолчанию, `requisites`, `dms`, `regulators`).

### Вкладка «Документы»

- `DocumentTable` в стиле `ServiceTable` / `DoctorTable`. Строки
  сгруппированы по категориям в порядке сайта; внутри группы — кнопки ↑/↓
  (без drag-and-drop), после сдвига — `PATCH /documents/order`.
- Колонки: название, тип (PDF / ссылка), дата обновления, действия «открыть»
  и «удалить». Удаление — через подтверждение в существующем `Modal`.
- Бейдж «Не хватает» у обязательной категории без документов. Правило —
  чистая функция `missingRequiredCategories` в `lib/admin/`, с тестом.

### `DocumentSheet`

- Поля: категория (select), название, примечание, переключатель
  «Файл / Ссылка».
- «Файл» — новый `FileDropzone`: только `application/pdf`, ≤ 30 МБ,
  загрузка через route handler, индикатор загрузки, после — имя и размер
  файла. Существующий `Dropzone` для картинок не меняется.
- «Ссылка» — поле URL с проверкой `https://`.
- Замена файла у существующего документа сохраняет запись и её позицию.
- Черновик (`lib/admin/draft`), защита от потери несохранённого и ошибки у
  полей — как в `DoctorSheet`.

### Вкладка «Реквизиты»

Одна форма из восьми полей и «Сохранить». Форматы ИНН/КПП/ОГРН проверяются
на клиенте (`lib/admin/validation.ts`) до запроса и повторно на бэкенде.

### Вкладки «ДМС» и «Контролирующие органы»

Небольшие таблицы: добавление и правка на месте через `InlineEdit`,
сортировка ↑/↓, удаление с подтверждением.

### После любого изменения

Серверный action вызывает `revalidateTag("disclosure")`.

## 4. Витрина

- `lib/cms.ts`: `getDisclosure()` — `GET /api/cms/disclosure` с
  `next: { tags: ["disclosure"], revalidate: 3600 }`.
- **При ошибке бэкенда `getDisclosure()` бросает**, а не возвращает `null`,
  как `fetchCms`. Иначе пустая страница раскрытия закешируется на час. При
  сбое фоновой ревалидации Next продолжит отдавать прошлую удачную версию;
  если удачной версии нет — `app/(site)/documents/error.tsx`: «Сведения
  временно недоступны, позвоните по номеру …» с `CLINIC.phone`.
- `lib/disclosure.ts` остаётся без данных, только чистые функции:
  `omsNotice`, `groupDocuments` (раскладка по категориям в порядке показа,
  без категорий врача), `guaranteeProgram` (документ `GUARANTEE_PROGRAM` или
  `null`).
- Разметка `/documents` прежняя. Подпись у документа: «PDF» для `FILE`,
  «Внешний сайт» для `LINK`; строка «Обновлено ДД.ММ.ГГГГ» из `updatedAt`.
- Телефон, почта и режим работы по-прежнему из `CLINIC` в `constants.ts`:
  их делят шапка, подвал и контакты, перенос — вне этой задачи.

## 5. Перенос данных и выкатка

Сида в коде нет — реквизиты в `CommandLineRunner` были бы тем же хардкодом.

1. **Релиз 1 — бэкенд и админка.** Витрина по-прежнему читает
   `lib/disclosure.ts`. Администратор заносит реквизиты, загружает пять
   текущих PDF (договор, прейскурант, выписка из реестра лицензий,
   налоговое свидетельство, Постановление № 659) и заполняет органы. Это и
   приёмка админки на настоящих данных.
2. **Релиз 2 — витрина.** `/documents` переходит на `getDisclosure()`; из
   `lib/disclosure.ts` удаляются данные, из `public/docs/` — PDF. В
   `next.config.ts` — постоянные редиректы `/docs/:path* → /documents`,
   чтобы проиндексированные ссылки не отдавали 404.

## 6. Тесты

- **Бэкенд** (JUnit, как существующие `*Test`): `@Pattern` реквизитов,
  сигнатура PDF (не-PDF с расширением `.pdf` → 400), отказ для не-`https`
  ссылок и `FILE` вне `/uploads/`, upsert реквизитов, `/order` с неполным
  списком → 400, `GET /disclosure` не отдаёт документы врачей.
- **Витрина** (vitest, чистые функции в `lib/`): `groupDocuments`,
  `guaranteeProgram`, `missingRequiredCategories`, валидация реквизитов.
  Тест «на каждый документ есть файл в `public/`» удаляется вместе с данными
  в релизе 2.
- **Компоненты** — сборка и ручная проверка в браузере, как в плане A.

## Вне рамок

- Документы врачей в интерфейсе — план B (модель и компоненты готовы).
- Отзывы и обращения граждан — план C.
- Перенос `CLINIC` (телефон, почта, режим работы) в админку.
