# Соответствие сайта клиники Постановлению Правительства РФ № 659 — дизайн

**Дата:** 2026-09-17
**Статус:** принято владельцем

## Задача

Привести сайт клиники «Премиум» в соответствие с требованиями к раскрытию
информации медицинской организацией (Постановление Правительства РФ № 659):
версия для слабовидящих, согласие на обработку персональных данных у каждой
формы, раздел раскрытия информации с реквизитами и документами, полные
сведения о врачах, форма отзывов и форма обращений граждан.

## Что уже есть в коде

Разведка по репозиторию на 2026-09-17 (ветка `feat/neuron-finale`):

| Требование | Состояние |
|---|---|
| Версия для слабовидящих | Есть одна кнопка-переключатель: `app/(site)/components/A11yToggle.tsx`, режим включается до первого пейнта (`app/layout.tsx`), стили — `app/globals.css:172`. Это один режим ×1.25 «чёрное на белом», а не панель по ГОСТ Р 52872 |
| Политика конфиденциальности | Страница `/privacy` есть |
| Галочка согласия у форм | Нет ни у одной формы |
| Формы сбора данных | На витрине ровно одна — `app/(site)/contacts/ContactForm.tsx` (EmailJS с клиента). Все кнопки «Записаться» — ссылки на `/contacts` |
| Раздел раскрытия информации | `/documents` — плоский список из 4 PDF, без реквизитов, ОМС/ДМС и контролирующих органов |
| Сведения о врачах | Модель врача — `id, imgSrc, name, specialty, bio` в `DoctorsEntity`, DTO и `lib/types.ts`. Образования, аккредитации, срока сертификата и графика нет |
| Отзывы | Нет |
| Обращения граждан | Нет |

Технические ограничения, влияющие на решения:

- Витрина — Next.js 16, `output: "standalone"`: серверные роуты доступны.
- Бэкенд — Spring Boot + Postgres, `ddl-auto: update`, миграционного
  инструмента в проекте нет: новые колонки и таблицы создаёт Hibernate.
- `SecurityConfig` отдаёт все `POST /api/cms/**` только роли ADMIN. Публичная
  отправка отзыва требует явного исключения и защиты от спама.
- Тесты — vitest, `environment: "node"`, `include: ["lib/**/*.test.ts"]`.
  DOM-окружения и testing-library в проекте нет: тестируются чистые функции в
  `lib/`, компоненты проверяются сборкой и вручную.

## Решения владельца

1. **Разбиение на три плана.** Требования ТЗ образуют три независимые
   подсистемы; каждая даёт работающий результат сама по себе.
2. **Версия для слабовидящих расширяется до ГОСТ Р 52872:** три размера
   шрифта, три цветовые схемы (чёрное на белом, белое на чёрном, коричневое на
   бежевом), межбуквенный интервал, изображения вкл/выкл.
3. **Отзывы — на своём бэкенде с модерацией:** новая сущность, публичный POST
   с защитой от спама, статусы PENDING/PUBLISHED, модерация в админке.
4. **Расширенные данные врачей — на бэкенде:** новые поля в `DoctorsEntity`,
   DTO и форме админки, чтобы клиника сама правила срок действия сертификата.

## Разбиение на планы

### План A — право и контент
Панель доступности по ГОСТ, согласие на обработку ПДн у форм, раздел
«Раскрытие информации»: реквизиты, документы, блок ОМС/ДМС, контролирующие
органы. Затрагивает только витрину, бэкенд не меняется.

### План B — врачи
Расширение модели врача на бэкенде (`DoctorsEntity`, DTO, контроллер), форма
в админке, переработка карточки и страницы врачей: ФИО полностью, должность и
специальность по диплому, образование, номер и срок действия сертификата,
график приёма.

### План C — интерактив
Сущность отзыва с модерацией, публичный эндпоинт с защитой от спама, форма
отзыва и лента опубликованных отзывов на витрине, модерация в админке, форма
официальных обращений и жалоб на имя руководства.

Порядок: A → B → C. План A не зависит от остальных; B и C независимы друг от
друга, но оба опираются на компонент согласия из плана A.

## Что нужно получить от клиники

Эти данные нельзя вывести из кода — без них разделы отрисуются, но останутся
пустыми:

1. Полное наименование ООО, ИНН, ОГРН, дата регистрации, юридический и
   фактический адрес.
2. PDF: утверждённый образец договора на оказание платных медицинских услуг,
   действующий прейскурант (совпадающий с кассой), скан медицинской лицензии
   со всеми приложениями, текст Постановления № 659.
3. PDF или ссылка: Территориальная программа госгарантий по Республике
   Башкортостан на текущий год.
4. Список страховых компаний-партнёров по ДМС.
5. По каждому врачу: ФИО полностью, должность, специальность по диплому, вуз и
   год окончания, специальность сертификата, его номер и срок действия,
   график приёма.
6. Адрес электронной почты руководства для официальных обращений.
