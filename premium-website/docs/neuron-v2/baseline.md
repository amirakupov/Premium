## Что замерено

| Метрика | Значение | Как получено |
|---|---|---|
| `tsc --noEmit` | 0 ошибок | `npx tsc --noEmit` |
| `npm run build` | успешно, 19 маршрутов | CMS API недоступен при сборке → срабатывает фолбэк, это ожидаемо |

Бюджет из ТЗ — прирост не более +40 KB gzip. Порог для финальной проверки:
**≤ 615 000 B** суммарно по клиентским чанкам.

Команда для повторного замера — та же, что в таблице; сравнивать нужно после
`rm -rf .next && npm run build`, иначе в `.next/static/chunks` остаются чанки
предыдущих сборок и сумма завышается.

## Что НЕ замерено и почему

- **Скриншоты секций «до»** — снять не могу: браузерная автоматизация в этой
  сессии не используется по договорённости с владельцем проекта.
- **FPS на трёх тирах** — то же. Целевые значения из ТЗ (60 fps десктоп,
  ≥ 30 fps iPhone 12 / средний Android) проверяются вручную.
- **LCP** — держится серверным постером в `NeuronHero.tsx`; постер сохраняется
  во всех этапах, но фактический замер за владельцем.

Эти три пункта закрываются замерами владельца проекта; в отчёте по этапам они
помечены как непроверенные мной, а не как выполненные.

## Известные ограничения v1 (диагноз, подтверждённый чтением кода)

1. Освещения нет вообще: дендриты и сома на `MeshBasicMaterial`, у всех
   материалов `toneMapped: false`. Объём давала только френель-аура на `BackSide`.
2. Ветви — `TubeGeometry` постоянного радиуса, конусности нет.
3. Сома — идеальный икосаэдр с плоской заливкой.
4. Bloom при `INTENSITY: 0.42` на светлом фоне почти no-op.
5. Хореография: одно вращение `rotation.y = time*0.08 + progress*2.2` плюс
   dolly 9.5 → 4.4 → 8.6 на три экрана.
6. 44 однотипных импульса, бесконечный цикл `% 1`, реакции на скролл нет.
7. `PAGES = 3`: ниже хиро сцены нет, анимирован только `ClinicFotos`.
8. `ScrollControls` держит собственный контейнер прокрутки — главный
   архитектурный блокер: конфликт с нативным скроллом, текст в `<Scroll html>`.
9. `placeSignals` аллоцирует `new THREE.Vector3()` каждый кадр.
